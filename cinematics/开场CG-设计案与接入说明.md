# 《疯狂修仙，中》开场 CG —— 设计案与接入说明

面向「初始界面 / 加载等待」的开场动画。目标不是做一支炫技短片，而是做一支**玩家看第二遍也不烦**的世界观开场：一条连续向下的长镜头，从云海之上落到村中桥头，用四层递进完成「世界 → 人间 → 人 → 悬念」的交付，最后收在标题卡上。

生成规格：25 秒 · 16:9 · 1920×1080 · 像素美术 + 电影感运镜 · 片尾只落标题卡（不含「点击开始」）。

---

## 1. 为什么这样设计

| 决策 | 理由 |
|---|---|
| **一镜到底，不切镜** | 加载页动画会被反复观看。快切剪辑第二遍就变成噪音，连续下降的镜头第二遍仍然舒服，也让玩家有「我在降落，而不是在看广告」的体感。 |
| **0–3 秒必须是奇观** | 玩家在这几秒里其实在等加载。第一眼就给「一座悬在云海上的仙村，一柱金光直冲天际」，才留得住人。 |
| **从宏观到微观的落点是人** | 先给格局（云海、五域、山门），再给烟火（灯笼、水车、药草、溪水），最后落到一个背影。前两层是世界观，第三层是「你就是他」。 |
| **结尾用剑气收** | 这是本作四技能之一「听风剑诀」的视觉语言，也是全片唯一一次动势爆发。留一个「他要去做什么」的钩子，正好接上标题卡。 |
| **标题卡单独出图，不烧进视频** | 标题要能改文案、能对多语言、要清晰不糊。视频收在深墨底色，标题由后期或引擎叠上去，改一个字都不用重生成。 |

## 2. 视觉设定

- **基底**：沿用 `assets/pixel/village-background.png` 的美术语汇——青灰瓦顶与木构飞檐、成串暖金灯笼、石拱桥与碧色溪流、山巅金色渡劫圆台与环形阵纹、远处暗紫魔龙石门。
- **像素规范**：单像素块约 3px（1920 宽下），全片统一；明暗过渡 3–4 级色阶，云缘为阶梯状硬边；玻璃感高光、真实镜头光斑、柔焦一律不用。
- **电影感来源**：不是靠模糊，而是靠**运镜、速度曲线与光比**——缓慢下降的机位、轻微侧滚、贴着瓦当的低空前滑、人物处的减速停顿、剑气后的上仰。
- **色板**：暖金（灯笼/阵纹/光柱）#F0C46A 区间 → 瓦灰青 #4A5560 区间 → 靛青暗部 #1B2633 区间 → 溪水碧 #2FB3A5 区间。全片保持暖冷对比，暗部略偏青。
- **人物**：三头身像素剑修，褐色高马尾 + 靛蓝发带、象牙白外袍配深蓝衣缘、背负长剑；**全程只出现背影**，不对镜头转身。背影既省去面部一致性风险，也让「你」更好代入。

## 4. 声音方案

- **人声**：无。加载页出现旁白会干扰玩家，也让重复观看变吵。
- **音乐**：直接复用游戏已有 `assets/audio/village_loop.wav` 做底床，与游戏音景同源，零额外成本。
- **音效**：灯笼轻铃（约 8 秒）、剑气破空＋低频轰鸣（约 19 秒）、收尾钟磬（约 22 秒）。这三处若要做，需另出音频；也可先只上音乐底床，画面本身已成立。

## 5. 后期合成（本机 ffmpeg 可直接执行）

```powershell
# 1) 成片拼接：23 秒生成画面 + 2 秒标题卡静帧 = 25 秒
ffmpeg -i op-opening-cg-raw.mp4 -loop 1 -t 2 -i op-title-card.png `
  -filter_complex "[1:v]scale=1920:1080,format=yuv420p,fade=t=in:st=0:d=0.6[t];[0:v][t]concat=n=2:v=1:a=0[v]" `
  -map "[v]" -c:v libx264 -crf 18 -pix_fmt yuv420p op-opening-cg.mp4

# 2) Godot 原生可播的 Ogg Theora 版本（本机必须全关键帧 + yuv444p）
ffmpeg -i op-opening-cg.mp4 -vf "fps=12" -c:v libtheora -q:v 6 -pix_fmt yuv444p -g 1 -c:a libvorbis -q:a 4 op-opening-cg.ogv
```

**OGV 编码的硬性要求**：本机 Godot 4.7.2（Compatibility / AMD Radeon 780M）播放常规 Theora 会出现大面积彩块。实测 `yuv420p`、`yuv422p` 全屏花屏，`yuv444p` 默认 GOP 仍有色块，`-g 12` 更严重；只有 **`yuv444p` + `-g 1`（全关键帧，无 P 帧）** 在 3、9、17 秒抽查中全部正常。当前文件为 1280×720、12fps、约 17.9MB。若希望运镜更顺滑，可改为 24fps，体积约翻倍；`op-opening-cg.mp4` 仍是 24fps 的成片，不受影响。

### 6.1 启动流程

1. 进入轻量启动场景，立刻显示首帧背景，不再白屏。
2. 桌面端存在 `op-opening-cg.ogv` 时播放开场 CG；网页端或视频缺失时直接进入静态等待界面。
3. 主场景资源按 `LOAD_QUEUE` **逐帧分段加载，每帧一项**，动画在帧间继续播放，进度条对应真实加载项。
4. CG 播完或被跳过后进入等待界面：标题卡整屏铺满，小人沿底部加载条往返奔跑。
5. 主场景读取完成并短暂停留后淡出，`change_scene_to_packed()` 切入 `scenes/main.tscn`。

### 6.2 为什么不用线程加载

实测 `ResourceLoader.load_threaded_request("res://scenes/main.tscn")` 在本工程会失败：`scripts/equipment_rules.gd` 在常量中 `preload("res://data/equipment-growth.v2.json")`，线程加载路径下出现 `Could not resolve external class member "GROWTH"` 与级联编译失败；开启子线程还会导致引擎访问冲突崩溃。直接同步读取主场景无任何错误，因此采用主线程逐帧分段加载，不引入线程风险。

**维护注意**：新增大型启动资源时，把它加入 `LOAD_QUEUE`，加载条才能继续反映真实进度。单项资源过重时仍会造成一次短暂卡顿，这是该方案的已知边界。

### 6.3 CG 不强制重复 25 秒

- 每次启动最多播放一次，不循环。
- 播放 1.2 秒后，点击、按键或触摸均可跳过。
- 若场景已就绪，CG 最多保留 6 秒即收尾，不要求玩家看完。
- 当前没有写入跨启动的“已看过”存档标记；如需只在首次启动播放，可再基于 `local` 存档增加标记。

### 6.4 循环小人不是额外视频

小人直接复用 `assets/pixel/cultivator-walk.png` 第三行的四帧行走图，以 `AtlasTexture` 切格，约 9fps 循环，并沿加载条往返、按方向翻转、带轻微上下起伏。它由正常渲染帧驱动，不依赖视频循环，因此 CG 结束、网页降级、主场景加载期间都能持续运动，也没有额外生成消耗或视频体积。

### 6.5 调试参数与验证

- `--splash-hold`：停留在等待界面，不继续加载主场景，便于检查布局。
- `--splash-shot=<path>`：2.5 秒后保存引擎内截图并退出。
- `--preview`、`--skip-intro`、`--skip-cg`、`--capture=...`：跳过 CG，保持既有自动化行为。
- 已通过：分段加载完整进入主场景的 headless 检查、等待界面 headless 检查、CG 在 3/9/17 秒的真实渲染抽查、等待界面渲染截图、加载后仙村完整界面截图。
- `--splash-cg-hold`：阻止主场景加载但不跳过 CG，配合 `--splash-shot=path@秒` 可抽查视频任意时间点。
- 曾误判一次：把引擎内截图的色块当成"截图读回问题"。用户实测确认彩屏真实存在，根因是 Theora 的 P 帧与色度子采样解码，已按第 5 节的全关键帧方案修复。
- 尚未验证：Web 导出与手机真机；网页端目前只保留静态降级分支。

### 6.6 回退

把 `project.godot` 的 `run/main_scene` 改回 `res://scenes/main.tscn` 即可恢复原启动方式；新增场景、脚本与素材可保留，不影响主场景。

### 6.7 网页端后续建议

Godot 的 Web 导出对 `VideoStreamPlayer` 支持不完整，官网大概率播不出视频。当前代码已走静态降级；若要让网页端也有“假动画”，可在等待界面上叠云层 UV 平移与光柱亮度脉动的轻着色器，无需新增素材。

## 8. 尚未解决 / 可继续决定

2. **声音**：当前保留模型环境音并在片尾前淡出；是否换成原创 BGM 或补剑气音效可另行制作。
3. **首次启动才播 CG**：当前每次启动播一次；如需永久记住“已看过”，再加本地存档标记。
4. **验证范围**：未做 Web 导出与手机真机验证，未测量接入前后的实际启动耗时。
