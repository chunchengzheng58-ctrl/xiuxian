# 新版试玩指南

本指南对应当前源码开发版。打开网页或继续使用已有游戏窗口，无法验证尚未导出、发布的新修改。

## 从正确的项目启动

主线版 Windows 输出目录为 `D:\Projects\ChatGPT\涅槃\outputs\campaign-preview\windows`。双击其中的 `Play.vbs` 即可使用随包运行时和本机服务，不需要安装 Godot、Node 或 npm；不要单独双击 `Xiuxian.exe`。默认账号库和缓存保存在包内 `data-save`，首次使用可注册测试账号；它与源码试玩服务及先前 `commercial-preview/windows` 的三关 r2 数据分开。主线玩法见 [五域归衡试玩](CAMPAIGN_PLAYTEST.md)，完整构建、升级及可选恢复说明见 [Windows 构建与运行](WINDOWS_BUILD.md)。

下面的步骤用于继续开发源码版本。

当前工作目录为 `D:\Projects\ChatGPT\涅槃\work\xiuxian-pages`。请从这个目录双击 `启动试玩.cmd`，或用 Godot 4.7.2 打开这里的 `project.godot` 后按 F5。启动脚本优先使用 `GODOT4` 环境变量，其次使用 D 盘工具目录中的引擎，最后兼容原 F 盘引擎。

账号服务需要 Node.js 24.13 或以上的 24.x。首次准备：

```powershell
Set-Location 'D:\Projects\ChatGPT\涅槃\work\xiuxian-pages\server'
npm.cmd ci
npm.cmd run dev
```

看到“本地服务已启动：http://127.0.0.1:8080”后保留该终端，另行打开游戏。依赖已经装好时，游戏登录页也会尝试自动启动本机服务。多人试玩建议先手动启动服务，避免关闭自动启动服务的游戏窗口时连带关闭它。

登录页的用户名为 3–32 位字母、数字或下划线，密码至少 12 位。注册时填写昵称并选择修仙形象。进入后选择「我的角色 · 本人」即可使用社交、交易与论剑；添加家人是独立功能。

「游客演示」可看地图、模拟家庭、祈愿和本地战斗。锻造、万宝集、同道录与实时好友论剑需要正式游戏账号。

## 建议试玩顺序

1. **地图入口**：点击底部「健康档案」「技能练习」「属性闯关」「聚宝阁」「天机碑」，应立即打开对应界面。地图上可行走的实体位置仍保留寻路交互。
2. **Boss 造型**：属性闯关长廊的 02 朽梁为残梁机关造型，03 涩节为低矮转轴机关造型，04 窃荣保留木心鹿形。点击卡片进入独立战场。
3. **主线与祈愿**：本人从「五域游历 / 主线」听取线索，再前往本章秘境。正式二十关及章节推进会保存，历练提升冒险等级；章节归衡对白确认后可领取一次奖励。没有已固定初始支持值时，会使用游戏支持值 50，不需要上传健康资料。通关获得灵气后，在聚宝阁查看余额、基础概率和累计传说保障，先选流派，再单抽或十连。确认每件结果都可从行囊找回；换流派不会清除保底次数。家人角色仍遵循自己的确认档案与独立钱包，不能通过改本地缓存增加正式余额。
4. **装备养成**：在行囊穿戴装备，打开「锻造台」查看强化消耗和下一等级属性。强化最高 +10；铭刻可以换流派。凑齐同流派 2/4 件后，在下一场 PVE 使用套装加成。分解前须卸下装备，确认弹窗显示返还锻材数；挂单中的装备需先撤单。
5. **交易**：用不同账号分别扮演买方和卖方。卖方在行囊选择未穿戴装备并定价上架；买方在万宝集按部位查找并购买。确认只成交一次、卖方收到灵气、买方收到原强化等级和流派的装备。「我的交易」可查询成交和撤单。
6. **社交**：两账号分别打开「同道录 / 好友」并保存社交名片。交换邀请码，发送并接受申请，再发送私信。另一窗口应显示新申请和未读标记。移除或屏蔽会清除双方这段会话，请用测试账号验证。
7. **匹配论剑**：在「论剑台 / 对战」设置公开昵称后点击「开始匹配」，排队期间可取消。单账号等满 15 秒后由 100 名固定虚拟玩家轮换补位。匹配、擂台和「我的战绩」应显示同一个 ID，重新登录后可查看最近 10 场。全服榜显示混合排序的前 30 名和累计游玩天数，同分真人优先；补位对局只写个人战绩。测试真人匹配时，让两个不同账号在 15 秒内分别排队；同分对手胜负为 +12/-12。
8. **好友切磋**：从匹配页顶部切换「好友切磋」，或从同道录点击「约战」。对方在 90 秒内接受后，双方进入擂台；倒计时结束开始战斗。确认战果出现在近期战绩，好友切磋不改变匹配积分。

多人测试可运行两次同一目录的启动脚本，分别登录两个账号；两端必须连接同一游戏服务。不要把同账号的第二个角色当作交易对方。同一角色同时在另一设备进入擂台时，后进入的连接会接管操作。

## 战斗操作

| 操作 | 用途 |
|---|---|
| WASD / 方向键 | 移动；移动方向决定出招朝向 |
| J | 普攻 |
| 1 | 听风剑诀 |
| 2 / 空格 | 踏云步 |
| 3 / K | 云罡护体 |
| 4 / R | 饕餮归元；本地长廊需按进度解锁，论剑统一开放 |

触屏使用摇杆和技能按钮。公开匹配和好友论剑每局 90 秒，双方使用统一基础数值，装备养成不会造成数值差距。短暂断线会等待恢复；战斗中认输判负。长廊、演武练习、好友论剑及资源产出型秘境各自结算，不能把练习胜利当作正式资源奖励。

## 数据保存与换版本

| 数据 | 默认位置 | 用途 |
|---|---|---|
| 服务端账号数据库 | 项目内 `server/var/` | 账号、资源、装备、交易、好友及服务端战果 |
| 启动脚本的客户端数据 | 项目内 `work/appdata/Godot/app_userdata/家族修真录 · 像素仙村/` | 按账号分开的客户端缓存、灵宠偏好及部分本机记录 |
| Godot 编辑器本机缓存 | 项目内 `output/accounts/` | F5 编辑器运行时的按账号缓存 |
| 旧版本单角色文件 | `output/local-save.json` 或运行环境的 `user://songfeng_pixel_progress.json` | 首次发现后通过导入界面确认归属 |

同一服务端上的正式资源可在重新登录后恢复。部分本机表现数据没有完整跨设备恢复；只复制客户端缓存不能替代服务端数据库。正式账号发现旧本机档时，可将其备份至账号缓存下 `legacy-archives/{account_id}/{fingerprint}.json`，原文件也保留；家人面板可查看并复制归档位置。旧档中的资源、装备、健康档案和通关只供离线查阅或手动恢复，不覆盖线上进度。备份后还需同步服务端，失败时保留界面供重试。

更新源码和引擎无需删除存档目录。服务端现可使用在线一致备份与校验恢复命令，步骤见 [数据库恢复指南](DATABASE_RECOVERY.md)；恢复始终写入新路径，不覆盖原库。客户端的灵宠偏好和旧档归档等资料仍需单独保留。若采用手工复制，则先退出游戏并停止对应服务，再整体备份 `server/var`；运行中单独复制 `game.sqlite` 可能遗漏 WAL 中的事务。不要用旧程序打开已经升级的数据库，程序会拒绝高版本数据库。

## 启动问题定位

| 现象 | 检查 |
|---|---|
| 脚本提示找不到 Godot | 设置 `GODOT4` 为实际 4.7.2 引擎路径，或从 Godot 编辑器打开当前目录 |
| 登录提示游戏服务未连接 | 在 `server/` 执行 `npm.cmd ci` 和 `npm.cmd run dev`，检查服务终端；默认端口为 8080 |
| 双击启动后看到旧内容 | 确认脚本所在目录；退出旧窗口后重新启动，不能用旧网页部署代替当前源码版本 |
| 健康识别/微信不可用 | 这些是独立服务，需要其配置与凭证；见 [整合说明](BCD_INTEGRATION.md) |
| 请求超时或余额暂未刷新 | 等待重连。祈愿点击「继续上次单抽/十连」按原请求确认；已扣费的结果无需再次凑足费用，其他次数待确认后恢复 |

游戏日志位于项目内 `work/play.log`；手动服务的启动终端可查看后端错误。报告问题时记录所在入口、操作步骤和提示内容即可，不需要提供密码或原始健康资料。

## 复现自动 PVE 联调

以下命令启动独立内存服务和真实 Godot 客户端，使用随机回环端口及独立 `APPDATA`，不读取正在试玩的数据库：

```powershell
Set-Location 'D:\Projects\ChatGPT\涅槃\work\xiuxian-pages\server'
npm.cmd run build
Set-Location ..
node tools/playtests/expedition-ui.mjs
```

`GODOT4_CONSOLE` 可覆盖引擎路径；脚本也接受项目目录和截图输出目录参数。过程文件位于项目 `work/playtests/`，默认截图在 `outputs/playtests/`。该联调覆盖新账号无健康档案、首关权威战斗、断线回到同一局、首通装备/材料奖励、后续关卡解锁和用战斗所得祈愿。`node tools/playtests/story-ui.mjs` 进一步验证注册、木章对白、三关战斗、付费强化、章节领奖、重开恢复及火域入口；完整二十关自然养成与保存由 `server/tests/campaign.test.ts` 验证，机制与迁移另有独立回归。

公开匹配与好友切磋的双客户端实机回归也已放入项目，使用同样的独立服务和目录：

```powershell
node tools/playtests/matchmaking-ui.mjs
node tools/playtests/friendly-duel-ui.mjs
```

公开匹配脚本从两个未互加好友、未设置名片的新账号开始，实际创建昵称、取消重排、自动入场、攻击、重连和击倒，再核对积分、胜负及榜单。好友脚本单独验证邀请与接受，并检查不生成匹配积分。
