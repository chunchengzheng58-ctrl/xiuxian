## 当前需要优先解决的流程差距

1. **扩大新手与养成覆盖**。本人首次 PVE 在尚无初始值时设置游戏支持值 50，不创建健康档案。当前服务端新账号从零资源/装备，仅靠正常首通和章节所得完成二十关、九章与结局，无额外刷关；后16关约35–71秒，每关三招与最终阶段机制均实际执行。原生GL走通真实注册、木域三关、所得装备付费强化、一次章节奖励与重开恢复。后续仍应覆盖更多装备组合、触屏操作和不同熟练程度玩家，不能把理想测试控制器的路线当作整体平衡完成。
2. **保持旧档归档边界**。已修复正式账号确认旧档后可能退回本地模式的问题：旧本机文件仅作独立归档，完成再次服务同步后才能进入游戏。真实客户端已验证备份可离线恢复、原文件保留、远端本人身份不变、321 灵气/17 锻材/原装备不被覆盖，以及同步/备份失败可恢复。该能力不等于把旧本机资源迁入线上账本。
3. **扩大交付版本验证**。最终 Web 导出已通过干净导入、release 导出、414 项 PCK 资源审计、未加测试桥的桌面/手机基础加载，以及两个真实浏览器账号的联网 PVE、社交、抽卡、锻造、交易、好友 PVP 和公开匹配。已实测权威等待重连及生命冻结、原局恢复、公开积分与排行榜、已结算抽卡丢回执后低余额恢复及刷新重登找回。编辑器插件、测试工具和健康样本已排除。静态导出合计 134,952,975 字节，ZIP 105,049,786 字节。Windows x64 独立试玩包已用官方 release 模板导出，随包运行时/VBS 服务启动、真实登录与保存、服务重启后同角色、服务身份复用和随包备份恢复 CLI 均通过；2739 个文件的 ZIP SHA 核对通过，ZIP 175,310,624 字节。Windows PCK 已实际加载确认包含最终祈愿恢复与钱包投影方法，正常无覆盖主场景退出码 0、无运行 ERROR；详见 [Windows 构建与运行](WINDOWS_BUILD.md)。弱网首屏性能、手机实战、长时运行和干净机器兼容仍需验证。源码与本地包成功不表示公网已更新。
4. **恢复能力**。数据库迁移保留版本上限和历史校验守卫；上一版本磁盘升级已验证余额、强化/铭刻装备、会话和账本保留。新增 WAL 在线一致备份与恢复到新路径命令，已用实际注册、PVE、装备、交易、社交和祈愿数据验证逐表恢复、幂等重放与继续成交。原文件、已有目标和附属文件均保留；详细演练与边界见 [数据库恢复指南](DATABASE_RECOVERY.md)。跨磁盘副本、定期备份安排和长期恢复仍需运营环境验证。
5. **长时间与触屏使用**。需验证浏览器刷新、切后台、移动端软键盘和技能布局、服务重启、多个游戏窗口、持续战斗与大量行囊。一次截图或模拟层测试无法覆盖这些行为。
6. **主线版本交付**。正式二十关、九章主线、一次性奖励、结局与独立冒险等级现已串联。追加迁移10保留旧三关历史、钱包、装备和保底，旧正式首通历练只补记一次。新版应导出到独立的 `outputs/campaign-preview/windows`，保留正在试玩的三关 r2；主线玩法见 [五域归衡试玩](CAMPAIGN_PLAYTEST.md)。导出物以本身清单和实机测试为准，源码通过不表示旧Web包或公网自动更新。
