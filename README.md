# 疯狂修仙，中

一款以像素仙村为起点的修仙 RPG。创建自己的修士，闯秘境、练招式、养装备，也可以组队探索、与好友论剑，或者参加公开匹配冲击榜单。项目由 Godot 客户端和独立游戏服务端组成。

[官网直接玩](https://madxiuxian.com/) · [Windows x64 下载](https://madxiuxian.com/downloads/xiuxian-20261127-shendun-v1-windows-x64.zip)

网页及 Windows 正式版统一版本为 `2026.11.27-shendun-v1`，共用官网正式服务器与同一账号的角色、好友和神遁榜。Windows 解压后直接运行 `Xiuxian.exe`，无需安装 Node.js 或另配 API。登录本人角色后，从「同道录 → 神遁榜」导入并确认当天记录；1 步＝1 丈，提供全服 / 好友与今日 / 本周榜。公开范围默认关闭，转换后的距离可反推步数。接入方法见 [PTDS 指南](docs/PTDS.md)。社群功能见 [社群说明](docs/SOCIAL_SYSTEM.md)。

本 README 对应当前源码开发版。启动脚本会加载它所在目录的项目；已打开的旧窗口、已导出的客户端和网页部署不会自动变成此版本。试玩步骤见 [新版试玩指南](docs/PLAYTEST_GUIDE.md)，交付前仍需完成的验证见 [发布核对](docs/RELEASE_READINESS.md)。

## 运行

用 Godot 4.7.2 打开本目录 `project.godot` 后按 F5；也可双击本目录的 `启动试玩.cmd`。本机账号服务需要 **Node.js 24.13 或以上的 24.x**。首次使用先在 `server/` 执行 `npm.cmd ci`；随后登录或注册时会尝试自动启动服务。也可手动在该目录执行 `npm.cmd run dev`，默认地址为 `http://127.0.0.1:8080`。Python 用于可选的健康识别和微信服务，不是账号服务的启动依赖。

启动后可注册自己的账号，拥有一个本人角色和最多两位家人。本人角色不占家人位置；好友、论剑和交易使用本人角色。登录账号的资源与装备由服务端确认，通过 `GameKernel` 路由业务命令；游客演示使用独立模拟数据。

## 三分钟体验

1. 注册并登录后选择「我的角色 · 本人」，从「五域游历 / 主线」听取线索，再进入本章正式秘境。通关获得历练、装备、灵气和锻材，完成章节后读归衡对白并领取一次性奖励；无需先添加家人或上传健康资料。完整路线见 [主线试玩](docs/CAMPAIGN_PLAYTEST.md)。
2. 从“属性试炼 / 属性闯关”进入问道长廊。二十只 Boss 共用一条可横向行走的长廊，每扇门展示对应的 Boss、战场预览和首通标记。
3. A / D 行走、Shift 加速、滚轮浏览；点击 Boss 直接进入它的独立战场，或走近按 E。上方区域按钮和下方 01—20 编号可快速定位。
4. 使用 J 普攻、1 听风剑诀、2 / 空格踏云步、3 / K 云罡护体。普攻需靠近命中才回灵，体力自动恢复。
5. 首通两个不同 Boss，解锁 4 / R 饕餮归元。吐纳时移动变慢，受到实际伤害会中断。
6. 战斗结束后返回长廊会保留位置。回健康档案补充资料并确认新档案，下一场战斗采用更新后的属性；既有通关进度保留。未绑定报告的角色仍可使用明确标注的模拟改善。
7. 演武台可练习同一套四技能，不增加首通或贡献。每次入场生命、灵力、体力补满；战斗不扣健康属性。

本地后端已实现账号、角色、任务、绑定授权、事务账本、抽卡、装备养成、社交、交易、实时好友论剑和个人 WebSocket 同步。`npm.cmd run demo` 使用隔离数据库运行模拟闭环。详见 [后端说明](server/README.md) 和 [整合说明](docs/BCD_INTEGRATION.md)。真实微信与模型服务需要各自配置和联调，不能用本地模拟结果证明其线上可用。

## 长廊与战场

总共二十只 Boss，不再展示五条属性各十档的挑战列表。所有门都可点击，建议培养档位用于提供难度参考，不作为属性入场门槛。

- 长廊：使用新制作的像素古寺走廊底图，角色可以实际行走，镜头横向跟随；鼠标滚轮可以独立浏览。
- 战场：`scenes/trials/b00.tscn` 至 `b19.tscn` 为二十个独立场景入口，各自绑定名字、精灵、出生点、场景布置和专属氛围。
- 底图：基于 PR #2 下载的七张地域美术。同地域 Boss 会共用地域底图，但拥有各自的场景配置；当前并非二十张独立绘制的背景。
- 结算：保存每只 Boss 的首通与最佳用时；返回长廊保留角色和镜头位置。首通两个不同 Boss 解锁饕餮归元。
- 战斗：普攻、四技能和攻击预警；具名 Boss 加载对应招式与阶段配置。长廊战果记录和资源产出型秘境是不同入口；尚未加入联网排行。
- 顺序解锁：新档只开放第 1 关，通关后永久开放下一关；已通关关卡可随时重玩。规则层同时拦截点击、E 键和直接入口，不能只靠界面禁用绕过。旧档已通关记录保留，已通关 Boss 及其下一关不会被新规则重新锁回。
- 技能难度：10—100 档的前摇从 0.85 秒逐步缩短至 0.45 秒，椭圆攻击范围（完整宽×高）从 250×160 扩大到 460×300。预警与命中判定共用范围参数；演武练习保留原来的宽松节奏。

### 连招与技巧（本地长廊与演示战斗）

- **三段连击**：按住 J 或连续按 J，段数依次为 1/3 → 2/3 → 3/3。第三剑自动变为**终结斩**：判定距离 210 → 250，伤害在第三段基础上再乘 1.30，破韧 4 → 9、回灵 5 → 13，伴随暗红薄刃、少量血气碎光、更长顿帧与更强震屏。普攻落空仍会清空段数，距离不足时提示当前与所需距离。
- **行云衔接**：普攻或剑气命中后 0.55 秒内按 1，可用听风剑诀取消普攻后摇；耗灵 18 → 12、冷却 2.4 → 1.6、伤害乘 1.30。它只取消后摇，不重置剑气自身冷却，无法无缝连发。
- **连击计数**：真实命中累计连击，2.6 秒无命中清零；每 5 连击 +4% 伤害，最多 +16%。受伤会清空连击与行云窗口，因此“贪刀”与“踏云闪避”需要权衡。
- **剑意联动**：普通普攻、终结斩、剑气命中分别充能 8、18、20；精准闪避充能 20，完整护盾抵挡充能 10。精准闪避已有 2 秒强化反击；完整抵挡也会返还 6 体力并开启 1.2 秒反击窗口。归元完成时清除迟滞。
- **赤霄剑域**：剑意满后按 5 / T，或点击桌面、触屏的“剑域”键。三式在 0.18、0.46、0.76 秒分别结算，攻击倍率为 1.4、1.6、3.4，破势压力为 5、7、22；沿用路径命中判定，可攻击路径上的 Boss 与小怪。展开期间可继续移动，其他攻击/技能暂时锁定，且不附带无敌。大招不为自身充能，但仍会累积破势与 Boss 怒意。
- **判定可读化**：进入普攻范围且可出剑时 Boss 脚下有淡青提示圈；终结就绪时双方脚下有暗红脉动双圈。Boss 蓄力会显示技能名、收缩聚气环与危险区，命中爆点区分普通、终结、行云与剑域三式。剑域只画薄边界、剑印和逐式暗红刀光，不用全屏色块遮挡角色或危险区。
- **受击与激怒**：Boss 受击会短暂红闪并小幅后仰，后仰只影响绘制，不移动判定。普通普攻、终结斩和剑气分别积累 12、27、30 点怒意；满 80 后，Boss 在收招或等待时进入 0.48 秒怒意蓄势，再选择原有招式回击。原招式的完整蓄力时长和危险区不变，不会贴身瞬发；破势期间不积累怒意。

上述新增规则由 `scripts/boss_rules.gd` 结算，用于本地长廊与演示战斗。正式主线秘境使用 `scripts/expedition_view.gd` 和服务端战斗规则，连击、剑意和大招的主线接入待后续完成。表现验证脚本：`godot --path . --script res://tests/combat_fx_preview.gd`，截图输出到 `output/fx-*.png`。

普攻不计入四技能。聚宝阁开放武器、衣服、鞋子、饰品四个装备槽；装备独立增加游戏战斗属性。饕餮玉扣仍是固定角色特征，以 2D 像素特效参与护盾与归元表现。技能数值与各档血量、伤害为玩法验证初值。

## 登录注册、本人角色与两位家人

- 用户名为 3—32 位字母、数字或下划线，密码为 12—128 位；注册时设置自己的昵称和修仙形象。支持密码登录、退出和换账号。
- 用户名和密码由 Node 游戏服务验证。密码使用随机盐 scrypt 存储；默认会话仅在内存使用。勾选“记住账号并保持登录（此设备）”后，在此设备保存账号名和会话令牌，不保存密码；再次进入时向服务端校验，主动退出或取消勾选会清除保存的令牌。服务端会话有效期为 7 天，数据库与个人存档不提交 Git。
- 网页首屏展示阵法动画、真实资源进度、已下载量、总大小和采样速度；同一版本资源优先使用浏览器缓存。更新版本、清理浏览器数据或更换设备后需重新下载；缓存不会省去引擎初始化。Web 导出与缓存发布步骤见 [网页加载说明](web/README.md)。
- 账号区域显示“我的角色 · 本人”；下面始终有两个老人位置。本人不能添加到家人位置中。本人和每位老人的任务、灵气、装备、属性和通关分别保存。
- 不同账号使用不同的本机缓存：编辑器 `output/accounts/{account_id}.json`，运行版本 `user://accounts/{account_id}.json`。正式账号的钱包、装备、社交、交易和服务端战果按账号读取；灵宠偏好、部分表现记录等本机数据尚未完整跨设备同步。
- 首次登录正式账号发现旧本机存档时，可选择备份旧档或使用服务端进度。备份是独立的本机归档，原文件保留；旧灵气、装备、健康档案和关卡记录不会转入线上账号。归档成功且再次同步服务端后才进入游戏；同步失败留在原界面重试。家人面板可以查看并复制归档路径，同一旧档指纹只登记给一个账号。
- 家人卡片可添加老人、编辑资料或代填健康信息；未提交的健康输入仅保留在当前表单中，关闭后清空。战斗和识别进行时先完成或取消再切换。
- 当前默认账号服务为本机 `127.0.0.1:8080`，接口说明见 [后端说明](server/README.md)。旧 Python 账号服务和 `server/account` 已移除。

## 灵宠相伴

四位免费同行伙伴：云团小狐、葫芦小龙、莲叶团雀和药草小鹿。首次登录可选择灵宠、设置昵称，之后可自由更换；灵宠跟随地图角色，并可通过点击或左侧入口打开聊天。

灵宠偏好属于账号，不占本人或两位老人位置。聊天按当前角色读取游戏任务和进度，提供文字与导航，不能发奖、改属性或执行脚本；退出账号清空对话。默认使用本地向导，可选 HTTP 服务遵循 [聊天接口说明](docs/COMPANION_API.md)，账号令牌只向显式授权的源地址发送。

基础规则保留 70/700 祈愿价格、五档品质、四个槽位、每日 100 灵气、四技能和二十 Boss；装备成长与累计祈愿保障由 [equipment-growth.v2.json](data/equipment-growth.v2.json) 补充。旧规则与历史审查见 [本地规则](data/pixel-game-rules.v1.json) 和 [逻辑与账本审查](docs/c-ledger-alignment-review.md)。

## 聚宝阁：每日习惯、祈愿与装备

- 底部导航的「聚宝阁」直接打开界面；主地图左侧的商铺也可点击前往或走近按 E。
- 每天首项由家属确认的有效习惯记录获得 100 灵气，同时保留修为 +10、灵印 +1。当天第二项或重复记录不重复发奖，漏记不清零。
- 新钱包从 0 开始，与旧版回合试玩的 `qi` 和战斗技能使用的灵力分开。单抽 70，十连 700，积攒七天可十连。
- 白／蓝／紫／金／红分别为普通、精良、史诗、传说、神话；卡片与装备槽按品质描边，并显示品质名称。
- 概率按初始支持值固定，在支持值 100 的 `[55,30,11,3.5,0.5]%` 与支持值 0 的 `[35,33,22,8,2]%` 之间线性变化。已有确认档案时使用其五项基础属性平均值，旧档案 HP 大于 100 时只在此规则内截为 100。本人首次进入正式 PVE 秘境时，若没有已固定值，则使用游戏支持值 50（不创建健康档案）；无需先上传体检资料。后续档案更新、换装备不改变已固定概率。
- 十连至少一件史诗或以上；自然结果不足时仅把最后一件提升至史诗。页面展示的是保底前概率。
- 累计未获得传说或神话的次数按角色保存。第 31 抽起逐步增加获得传说的机会，最多第 50 抽必得传说或以上；抽到传说或神话后清零。十连中的每一抽分别计数，换流派不清零。旧档从新版计数 0 开始。
- 祈愿可选「苍梧生息」「白羽剑意」「玄泽踏云」或随机流派。选择流派只决定新装备的铭刻，不改变品质、部位和模板抽取规则。
- 五种装备模板包括攻击武器、防御衣服、生命衣服、体力鞋子、灵力饰品，每个槽位只穿一件；重复装备分别保留。精良踏风靴提供体力上限 +10。
- 点击结果卡可查看详情、比较当前装备并穿戴；背包支持槽位筛选。加成只影响下一场战斗快照，不改变健康属性。
- 正式账号的扣费、装备和请求回执由同一服务端事务结算；游客演示在本地存档原子保存。画面在结算成功后播放，跳过动画不改变结果。网络结果未确认时保留原请求编号，再试使用同一编号，避免重复扣费。
- 上次结果待确认时，按钮显示「继续上次单抽」或「继续上次十连」，其他次数和流派暂时锁定。确认已结算结果不需要再次备足抽卡费用，跳过动画不会改变恢复状态；重新登录仍可按原请求找回。
- 旧本地演示存档在离线升级家人结构时备份为 `*-before-accounts-v8.json`，保留其本地健康档案与通关；旧版当天奖励补入也仅适用于该离线存档。正式账号使用独立服务端资源，旧本机档仅作归档，不据此补发可交易资源。
- 游客试玩使用本地进度。游戏账号的祈愿、装备和交易由服务端账本结算。
- 登录后使用本人角色打开「万宝集」，可按部位浏览、购买装备和查询自己的交易。在「我的行囊」选择未穿戴装备即可定价上架，成交前可撤单。成交时灵气进入卖方钱包，装备进入买方行囊。
- 登录账号后打开「锻造台」：强化最高 +10；铭刻更换流派；分解未穿戴、未上架装备换锻材。同流派穿戴 2 件或 4 件获得套装效果，旧装备保留原数值并可自行铭刻。强化与套装只作用于下一场 PVE 的战斗快照，论剑使用统一数值。

## 论剑台

- 本人角色打开「论剑台 / 对战」，设置独立的公开昵称后即可开始匹配，不需要先添加好友。队列最多等待 60 秒，可随时取消；停留页面时匹配成功会自动入场，离开后可返回继续。
- 积分从 1000 开始，服务端按权威战果更新积分、胜负和公开榜。相同积分的双方分出胜负时为 +12/-12；具体变化随双方原积分变化。准备阶段离开、未能入场、服务中断或角色状态变化不计分，开战后认输或掉线超时正常结算。公开榜只使用社交昵称。

- 开战后认输会判负，短暂断线会等待重连。战果保存在论剑台的近期战绩中。

## 健康接口与存档

已按 GitHub `1f356a0` 的最新版 `health-entry` 接入原生像素界面：启动选择家人 → 为选中的家人填写信息，可选择形象 → 上传多张体检报告 / 病历 / 用药图片及文字信息 → 使用 `qwen3-vl-plus` 提取 → 原版规则引擎计算 → 预览最终属性 → 确认锁定后进入仙村。新版已移除五行，改为身体系统对应属性。药品通用名与商品名分离，每条资料只归入一个系统；创建页只保留玩家自行上传和填写资料，不显示样例按钮或相关提示。

在 `health-entry/.env` 填写 `LLM_API_KEY`，保留 `LLM_MODEL=qwen3-vl-plus`。游戏尝试自动启动本地服务；连接失败时双击 `health-entry/start.bat` 再重新连接。填写配置后无需重启。队友先运行 `python -m pip install -r health-entry/requirements.txt`。

可添加最多 6 张 PNG / JPEG / WebP（单张 10 MB，合计 30 MB），也可填写文字病史、用药与基本信息。文字模式只用规则、不调用模型。模型识别和文字计算分别标明。姓名、年龄、性别和关系均为必填，姓名与年龄初始留空，性别和关系也不预填。未上传照片时只显示文字占位，上传后才预览所选报告。游戏界面仅展示最终属性，不提供计算依据或公式入口。确认的姓名用于家人识别，修仙称号显示在角色旁；确认前不改数值，修改资料后需重新分析。

接口的 `hp_max`、攻击、灵力、体力直接进入战斗，不重复套用旧评分换算。保存洞察、心志、身法、气运和属性依据，不增加新的战斗机制。补充报告不会清空通关和技能解锁。完整说明见 `docs/health-entry-integration.md`；未绑定报告的角色仍兼容旧版 JSON 和模拟档案。

计划记录继续每日去重并积累修为，不把一次记录自动解释为真实健康改善。战斗生命归零仅表示本局失败，不根据健康分数自动推断现实死亡。公开匹配、累计积分榜和好友切磋均使用服务端实时战斗；当前积分榜不按赛季重置，也不提供逐帧复盘。

本机存档 schema 8 分别保存账号、本人角色、两位老人及当前角色；离线旧结构升级保留原有技能与记录。正式账号的旧档确认只创建独立归档，不覆盖服务端角色、资源和通关。旧单角色文件为编辑器的 `output/local-save.json` 或运行环境的 `user://songfeng_pixel_progress.json`。自动测试、预览截图使用独立数据，不写玩家存档。

`启动试玩.cmd` 将该次运行的 `APPDATA` 指向项目内 `work/appdata`，所以本地客户端缓存也保存在 D 盘项目中。Godot 编辑器直接 F5 使用编辑器存档路径；两种方式的本机表现缓存不同。游戏服务数据库独立位于 `server/var/game.sqlite`。不要删除这两个目录来“更新版本”；备份与恢复范围见 [新版试玩指南](docs/PLAYTEST_GUIDE.md)。

## 团队协作

仓库：<https://github.com/Oii6111/xiuxian>。

仓库所有者在 GitHub 的 **Settings → Collaborators** 中邀请队友，队友接受邀请后即可推送代码。每个人先克隆到自己的电脑，用 Godot 4.7.2 打开 `project.godot`；首次导入时会自动生成 `.godot/` 缓存。启动脚本中的引擎路径为本机路径，其他电脑可直接从 Godot 编辑器启动。

```bash
git clone https://github.com/Oii6111/xiuxian.git
cd xiuxian
git switch -c feature/your-task
```

开始新任务前，先回到 `main` 并拉取最新代码，再创建自己的功能分支：

```bash
git switch main
git pull --ff-only
git switch -c feature/your-next-task
```

完成修改并在 Godot 中验证后，提交并推送自己的分支，然后在 GitHub 发起 Pull Request，合并到 `main`：

```bash
git add .
git commit -m "Describe your change"
git push -u origin HEAD
```

Git 支持多人分别修改、提交和合并；需要实时一起编辑时，要另用实时协作工具。分工时尽量由一人负责一个 `.tscn` 场景或 `.tres` 资源，减少同时修改同一文件产生的冲突。脚本 `.gd`、对应 `.uid`、场景、素材和 `.import` 导入配置应一并提交；`.godot/`、本地存档、日志和更新备份已由 `.gitignore` 排除。
